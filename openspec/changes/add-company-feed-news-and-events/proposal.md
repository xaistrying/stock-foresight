## Why

The News Context agent reads three general RSS feeds, and on 2026-10-08 none of 130 items named SAB or Sabeco (`docs/DISCUSSION_describe_not_vote_redesign.md`, "News Context"). VCI, reached through `vnstock`, supplies per-ticker company announcements (`Company.news()`) and corporate events (`Company.events()`): dividends and ex-dates, shareholder meetings, share issues, director deals. Each call is capped at 50 items, so the history it can supply is partial: 4 to 16 months of news, and 8 months to about 9 years of events depending on the ticker (measured 2026-10-09 on SAB, VPB, VCB, VHM, SSI, HPG). The RSS feeds hold only about four days and cannot be backfilled at all. Any item not recorded now is an item the later readings (P2b) and the event-window study (S2) cannot use.

This is step 2a of the redesign: a data layer that fetches, cleans, stores and snapshots these items, and starts the snapshot clock now. It feeds nothing and shows nothing. The owner decided on 2026-10-09 (decisions 3 to 6) that it is for personal use, uses no API key, pins the vendor library exactly, does not feed the News agent, and logs into a file of its own.

## What Changes

- **New module `backend/app/services/company_feed/`** that fetches VCI company news and events for a given ticker through the project's vnstock wrapper (source `vci`, set explicitly), cleans every text field with the existing `_clean` from `news_feeds.py`, and stores new items. Titles keep their original language: no translation, no language-model call anywhere.
- **New SQLite file `backend/data/company_feed_log.db`**, created on first write by its own init function, with two append-only tables: `company_feed_item` (one row per distinct item version, keyed by ticker, source, kind, item id and content hash, with `fetched_at` of first sight) and `company_feed_fetch` (one row per fetch attempt, including empty and failed ones). It is not `app.db` (disposable) and not `debate_log.db` (whose spec stores no third-party headline text).
- **RSS items are snapshotted too**, through the existing bounded feed fetch, into the same tables with no ticker, because the feeds cannot be backfilled.
- **New script `backend/scripts/snapshot_company_feed.py`**, run by hand (and safe to run from cron), is the only trigger. No debate hook, no Refresh or load path and no startup hook calls it. Reasons are in design Decision 1; the main one is that a vnai rate-limit `SystemExit` raised inside the server process ends the server.
- **Failures are non-fatal and never silent**, following the `debate-outcome-log` pattern: ERROR log with traceback naming ticker and kind, a `company_feed_fetch` row with the status, the run continues, the exit code is non-zero. vnai's rate limit is paced under and survived with the same handling `bulk_ingestion` and `macro.py` use.
- **Exact pin** in `backend/requirements.txt`: `vnstock==4.0.5` and `vnai==2.5.5` (both are what the venv has and what `docs/KNOWN_ISSUES.md` verified the guard against), with a comment stating how a bump is done.
- **Docs at apply time**: `docs/KNOWN_ISSUES.md` (the second irreplaceable file joins the backup note; the "no version pin" item is closed), `docs/DATA_DICTIONARY.md` (the new file and tables).
- **Out of scope**: feeding the News agent, any UI or API endpoint, the readings and coverage display (P2b), the event-window study (S2), fundamentals (P4), an API key, translation or any model gist, pagination past 50 items, a scheduler.
