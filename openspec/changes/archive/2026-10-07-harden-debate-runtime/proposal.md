## Why

`POST /tickers/{ticker}/debate` is the product's only live output now that the XGBoost return model is being retired, and it is unsafe and unpredictable to run. The 2026-10-06 post-pivot review (`docs/DISCUSSION_post_pivot_review.md`) listed the gaps; each was re-checked against the tree at commit `e77986e`:

- **Timeouts.** The OpenAI and Anthropic calls set no timeout of their own: the installed SDKs default to a 600 s read timeout and 2 automatic retries (checked on the installed versions, openai 3.24.0 and anthropic 1.11.0), so one hung call can hold a run for many minutes. `claude_cli` has a hard-coded 120 s ceiling and no retry. A new SDK client is built per call. The frontend `fetch` has no abort, so the browser waits indefinitely.
- **No limits.** Each run makes up to 8 LLM calls (3 + 3 + 2), 3 RSS fetches and up to 3 market-data fetches; with `claude_cli` up to 3 concurrent subprocesses per stage. Nothing stops a double click, a second tab or a script from starting ten of them, and nothing joins two requests for the same ticker.
- **Avoidable latency.** The two synthesiser calls are independent but awaited one after the other (`synthesiser.py:115-118`). SQLite reads, the HAR-RV `pickle.load` (about 2.8 s on the first call, measured in the review) and the report write run on the event loop. The README says one Analyse takes about 45-50 s on `claude_cli`; the panel's source comment says 4-8 s, and no run records where its time goes.
- **Config errors.** An invalid `DEBATE_LLM_EFFORT` (or a non-numeric `DEBATE_MAX_TOKENS_PER_CALL`) raises in `LLMClient.__init__`, which `DebateEngine()` calls outside any handler (`debate.py:73`): HTTP 500 with no message. Worse, an unknown provider, a missing API key or a missing `claude` binary fails inside each agent's own `try`, and the run returns HTTP 200 with three neutral agents (OBSERVE, unanimous).
- **Untrusted text.** Only the News Round 1 prompt calls its input untrusted and says "do not recommend". Headlines are cleaned and capped (`news_feeds.py:178-186`) but not fenced, and headline-derived bullets are pasted unfenced into every Round 2 prompt and both synthesiser prompts. A blank or refused synthesis reply is shown under "Key Tension".
- **Dishonest status.** `DebatePanel.jsx:122` always prints "Report saved to reports/...", while an export failure is only logged (`debate.py:76-81`).
- **Panel runtime UX.** "Running agents..." is static, `startTime` (`:164`) is dead state, switching ticker calls `mutation.reset()` during render and throws away a finished (possibly 45 s) result, and every failure but 404 reads "Analysis failed - please try again".

The review's figures are the reviewers' own measurements, not reproduced by us; this change adds a task that reproduces the ones it relies on (SDK defaults, call counts, stage structure, event-loop stalls) with stubbed providers, and keeps the script.

## What Changes

- **LLM client**: one explicit per-call ceiling (`DEBATE_LLM_CALL_TIMEOUT_SECONDS`, default 60 s, all providers, replacing the hard-coded 120 s), one retry policy (SDK retries capped at 1 for the API providers; one retry for `claude_cli` failures that are not timeouts), one SDK client per process instead of per call.
- **Run budget**: `DEBATE_RUN_TIMEOUT_SECONDS` (default 180 s). Expiry cancels the run (child processes are killed) and answers HTTP 504 with `code: "debate_timeout"`; no partial verdict.
- **Run control** (new `runner`): requests for a ticker already running join that run instead of starting another; at most `DEBATE_MAX_CONCURRENT_RUNS` (default 2) runs per process, otherwise HTTP 429 with `Retry-After` and `code: "debate_busy"` (reject, not queue). New `GET /tickers/{ticker}/debate/progress` reports `{running, stage, elapsed_ms}` for the panel. The run lives in a task owned by the runner, so an aborted client does not strand a half-finished run, and the report export runs inside it. After the run and the export, and before any caller gets the response, the runner calls registered **post-run hooks once per run** (not once per HTTP request, so joined requests do not repeat them); `debate-outcome-log` plugs its `debate_log` write into this hook. A hook failure is logged loudly and never fails the response.
- **Config preflight**: an invalid or incomplete LLM configuration is reported before any run starts, as HTTP 503 with `code: "debate_not_configured"` and a message naming the variable (never its value).
- **Latency**: the two synthesiser calls run concurrently; blocking SQLite, pickle and file work moves off the event loop; each run logs one line with per-stage durations (`round1_ms`, `round2_ms`, `synthesis_ms`, `total_ms`) and the provider.
- **Prompts and outputs**: every prompt that carries scraped or peer-agent text fences it and says "describe, do not recommend buying or selling"; the synthesiser prompt receives stance counts, not the verdict enum name; model output goes through a narrow check that withholds recommendation-style sentences (it does not mark an agent degraded and does not change a vote); a blank, too-short or refusal-style synthesis reply becomes `key_tension: null`, shown and exported as "unavailable".
- **Response**: adds `report_saved` and `report_file`; `synthesis.key_tension` becomes nullable. These are the only contract changes; the verdict enum is untouched.
- **Frontend**: stage label (from the server) and elapsed seconds while running; the last result per ticker is kept in memory and an in-flight run survives a ticker switch; a client time limit (200 s) with a clear message; reason-specific messages for busy, not configured, server timeout and client timeout; the report line only when `report_saved` is true; dead state, the 4-8 s comment and `mutation.reset()` in render removed.
- **Docs**: README latency/config section; `docs/KNOWN_ISSUES.md` entry for "no auth on `/debate`, per-process limits".
- Owner rulings recorded here (2026-10-07): limits kept as drafted (60 s per call, 180 s per run, 2 concurrent runs per process); over the cap the request is rejected with 429, not queued; the advice-wording filter may withhold a bullet that relays a named broker's recommendation (accepted trade-off); the progress endpoint stays.
- Not in this change: authentication (personal localhost app; recorded with the rationale), eligibility rules and the `agents_degraded` marker (`debate-data-guards`), label strings and the disclaimer (`align-rules-and-disclaimer`), outcome logging (`debate-outcome-log`), model preload (`calibrate-volatility-range`), scaling to many tickers or a verdict Rail, server-side cancellation when a client disconnects.

## Capabilities

### New Capabilities
- `debate-runtime`: how a debate run is bounded and observed: LLM call and run time budgets, retry, per-process concurrency cap with in-flight de-duplication, progress reporting, configuration preflight, event-loop hygiene, per-stage timing logs, the prompt contract for untrusted text, the output check for recommendation wording, handling of unusable synthesis text, and the `report_saved` / `report_file` response fields.

### Modified Capabilities
- `news-agent`: new requirement that headlines are fenced as untrusted data in both News prompts (ADDED; the existing "untrusted, do not recommend" sentence in the Round 1 prompt is kept).
- `debate-panel-ui`: new requirements (ADDED, distinct names) for running-state progress, per-ticker result retention, the client time limit, reason-specific failure messages and the conditional report line. No existing requirement is modified.

## Impact

- **Domain rules**: Rule 6 (never frame output as investment advice) is honored unchanged and strengthened for LLM text; no sign-off needed. Rule 5 (labels), Rule 2 (percentages) and the disclaimer text are not touched; the labels in the stage text are not verdict labels. Rules 1, 3 and 4 are not touched.
- **Backend code**: `app/services/debate/llm_client.py`, `engine.py`, `synthesiser.py`, `technical.py`, `macro.py`, `news.py`, `export.py`; new `app/services/debate/runner.py` and `prompt_safety.py`; `app/api/debate.py`; `app/main.py` (client close in `lifespan`). Tests: `test_llm_client.py`, `test_debate_agents.py`, `test_debate_export_api.py` plus new runner, prompt-safety and endpoint tests.
- **Frontend code**: `api/client.js`, `api/tickers.js`, `hooks/useDebateAnalysis.js`, new `hooks/useDebateProgress.js`, `components/DebatePanel/DebatePanel.jsx` and its test, `App.jsx` (panel keyed by ticker).
- **API**: new `GET /tickers/{ticker}/debate/progress`; new statuses 429, 503 (`debate_not_configured`), 504 on `POST /debate`; new response fields `report_saved`, `report_file`; `synthesis.key_tension` nullable. No schema, dependency or model change.
- **Third-party data**: ticker symbols, indicator values and public RSS headlines already go to the configured LLM provider; this change adds no new data flow. Credentials are only ever checked for presence, never logged or returned.
- **Sibling changes and apply order** (owner ruling): `debate-data-guards`, then `calibrate-volatility-range`, then this change, then `debate-outcome-log`.
  - `debate-data-guards` first: it owns `engine.py` / `synthesiser.py` semantics (`agents_degraded`, `INSUFFICIENT_DATA`, eligibility). This change only times, bounds and parallelises those calls; a call that times out ends as a degraded agent under their definition. Expect textual merge work in `DebateEngine.run`, `_safe_run` and `_serialise_result`.
  - `calibrate-volatility-range` second: it renames the result's `volatility_range_pct` to `range_5s_pct` (+ `sigma_daily_pct`) and owns the model preload; this change wraps whichever volatility call the Technical agent makes in `asyncio.to_thread`.
  - `align-rules-and-disclaimer`: owns label and disclaimer strings in `debate-panel-ui`, `debate-report-export` and `debate-synthesiser`. This change adds no label strings and ADDS (does not modify) panel requirements.
  - `debate-outcome-log` last, and it will be amended to register its writer with this change's post-run hook (design Decision 14, requirement "Post-run hooks run once per run") instead of writing from the endpoint, so the `debate_log` row is written once per run even when several requests joined it.
  - `retire-direction-model` and `app/main.py`: both edit `lifespan`. `retire-direction-model` removes the XGBoost model load (`app.state.model = xgb.Booster()` and its `load_model`) and the imports it leaves unused; this change only adds the LLM client close after `yield`. The edits touch different lines; whichever lands second leaves the other's lines unchanged.
- **Deviation from the shared contract**: none to existing names. Two additions the contract does not list: `report_file` (next to `report_saved`) and `synthesis.key_tension` nullable; both flagged in design.md Open Questions.
