## Why

The XGBoost direction model was retired as a product decision on 2026-10-05 (`multi-agent-debate-analyst`: pooled out-of-fold hit-rate 47.8%, corr ~0.01), but the 2026-10-06 post-pivot review (`docs/DISCUSSION_post_pivot_review.md`, Finding 5) found it still runs the app: it is a hard startup dependency, the headline Prediction card, the chart's projected point, the source of the Fresh/Stale dot, and the reason the page fires a prefetch burst per ticker chip. The review's figures are its reviewers' measurements; this change re-verified the ones it relies on against commit e77986e (see design.md, Context) and corrected two of them.

- **A fresh clone cannot start the app or run most of the API tests.** `backend/app/main.py:33-34` loads `pooled_xgb_model.json`, which is gitignored (`backend/.gitignore`, `data/models/*`). Measured in this session on a `git clone --local` of e77986e with the project venv: `pytest backend/tests` gives 1 failed, 368 passed, 1 skipped, 49 errors. All 49 errors are `XGBoostError` raised by the lifespan load in tests that use `TestClient(app)`; the failure is the real-database test `test_filter_clean_labeled_excludes_near_gap_and_null_target_rows`.
- **A retired model is still displayed.** `PredictionDisplay` shows `predicted_log_return` as a headline percentage with no disclaimer, the chart draws it as a dashed point, `AIInsightPanel` shows a Confidence, Advice and Technical Signal built on it, and `VITE_DEBATE_PANEL_ENABLED` (unset means off) decides whether the debate or the old panel is visible.
- **The page load is heavier than it needs to be.** Every Watchlist chip prefetches `/prediction`, `/history` and `/insight`. The review estimated about 1 + 3 x 599 = 1,800 requests. From the code and a read-only query of `backend/data/app.db` the figure is **1 + 3 x 208 = 625** (derived, not measured in a browser): `GET /tickers` returns the 208 symbols that pass the universe filters, not the 599 rows of `tickers`.

The owner has decided to stop serving XGBoost and keep the purged walk-forward helpers. This change removes everything that serves or displays the direction prediction and replaces the card and the chart point with the calibrated range from `calibrate-volatility-range`.

## What Changes

- **Backend removal.** The XGBoost load in `main.py`'s lifespan; `GET /tickers/{ticker}/prediction`; `GET /tickers/{ticker}/insight`; `POST /tickers/{ticker}/backtest`; `app/ml/backtest.py`; `train_xgb_model`, `train_final_model`, `XGB_PARAMS`, `MODEL_PATH`, `assemble_feature_matrix`, `load_training_features`; `verify_backtest_predictions.py`; the Finding 1 and 2 parts of `baseline_model_diagnostics.py`; the tests that encode all of the above; the `xgboost` requirement. The app boots with no model artifact on disk.
- **Kept and relocated.** `get_features_computed` and `get_latest_features_row` move from `app/api/predictions.py` to a new `app/services/feature_rows.py` (imported by `debate.py` and `technical.py`). The walk-forward fold helpers stay in `app/ml/training.py` (`compute_fold_boundaries`, `purge_training_rows`, `_label_dates_by_ticker`, `filter_clean_labeled`, `N_FOLDS`, `TARGET_HORIZON`, `FEATURE_COLUMNS`), because `evaluate_cross_sectional_momentum.py` and its test use them.
- **Data left alone.** `backtest_predictions` keeps its 10,191 rows; nothing writes or reads it and `init_db()` stops creating it on a new database. No `DROP`, no migration. `pooled_xgb_model.json` stays on disk (gitignored); it is not deleted.
- **Frontend removal.** `PredictionDisplay`, `AIInsightPanel` and its "Backtest this ticker" action, `useBacktestTicker`, `useTickerPrediction`, `useTickerInsight`, `useTickerFreshness`; the `VITE_DEBATE_PANEL_ENABLED` flag (the `DebatePanel` renders unconditionally); the Fresh/Stale dot, its legend and its CSS; the per-chip `/prediction`, `/history` and `/insight` prefetch in `TickerChip` ("Loaded Nd ago" and the Refresh icon stay); the dangling `./types` JSDoc import in `api/tickers.js`.
- **Frontend replacement.** A `RangeDisplay` card (typical 5-session move, as-of date, nominal coverage, measured range hit-rate worded "N of the last M five-session moves", rendered only here) and a range band on the chart at the t+5 date (dashed upper and lower bounds at `close x (1 +/- range_5s_pct/100)` with a light fill, symmetric, no direction), both from `GET /tickers/{ticker}/range`, fetched for the selected ticker only.
- **Request budget.** Page load with nothing selected: one request (`GET /tickers`). Selecting a ticker adds `GET /history` and `GET /range` for that ticker. Nothing is prefetched per chip.
- **Spec deltas.** `ticker-prediction`: the nine requirements REMOVED one by one and a stub requirement added recording the retirement (an archive run in a scratch copy rejected a capability emptied of all requirements). `dashboard-ui`: Prediction, log-return conversion, Confidence, Backtest, Advice, Sentiment, freshness, unselected-state, chart-point, disclaimer, load-refresh and panel-rendering requirements REMOVED and re-stated under new names (an archive run rejects a MODIFIED block that drops a scenario, so a requirement whose scenarios change is replaced, not modified); the legend requirement MODIFIED; range display (the only surface that renders `range_hit_rate`), range states, range-content limits and request-budget requirements ADDED. `model-training-pipeline` and `model-backtest`: XGBoost requirements REMOVED, walk-forward requirements kept and reworded. `ticker-catalog`: wording only (`in_training_set` kept). `ticker-manual-refresh`: freshness and prediction/insight wording replaced (a capability outside the stated ownership list, touched only because this change invalidates its text). `debate-panel-ui`: the feature-flag requirement REMOVED.
- **BREAKING** (API): `/prediction`, `/insight` and `POST /backtest` return 404. The only in-repo consumer is the dashboard, which this change updates. **BREAKING** (build): `VITE_DEBATE_PANEL_ENABLED` is ignored. The tracked `frontend/.env*` files also contain it; this change does not edit them (the owner's instruction), so the variable stays there as an unused, harmless line. `README.md` mentions it and is updated.
