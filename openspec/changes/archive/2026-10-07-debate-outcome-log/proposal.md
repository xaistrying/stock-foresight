## Why

Nothing the product now outputs can be scored. A debate run leaves behind only `reports/YYYY-MM-DD_<TICKER>.md`: gitignored, overwritten per ticker and date, and without the close at `as_of`, the model version, the LLM model, the headlines or the macro values (`docs/DISCUSSION_post_pivot_review.md`, Finding 4). The 2026-10-06 review measured that the shipped range covers about a third of 5-session moves and that the technical vote has no directional edge on history; it also noted that the News and Macro agents read live data (`macro.py` uses today's date, news is the last 7 days of RSS), so they cannot be backtested at all, only evaluated going forward. Every run that is not recorded now is evidence that cannot be recreated later, and `docs/DISCUSSION_prediction_outcome_tracking.md` (options 2 and 3) has been open since 2026-08-12. The owner has decided to pursue outcome tracking; this change does the minimum that makes verdicts and the displayed band scoreable.

## What Changes

- **New table `debate_log` in its own SQLite file**, `backend/data/debate_log.db` (gitignored by `data/*.db`), created on first write by its own init function with `CREATE TABLE IF NOT EXISTS`; `app.db` and its `init_db` are untouched. The file is separate because `app.db` is documented as rebuildable and the log cannot be rebuilt. One row per debate run, every run kept: ticker, `as_of` (the features-row date, never today), `run_at`, `close_at_asof` captured at log time, the band (`sigma_daily_pct`, `range_5s_pct`, `range_k`, `range_coverage`), eligibility, data age, degraded agents, all six stances, verdict and agreement level, model-file hash, LLM provider/model/effort, code revision, and a small JSON `evidence` column (technical inputs, headline ids, macro signal values). Outcome columns are nullable and filled later.
- **Write point**: the writer is registered as the post-run hook of `harden-debate-runtime`'s runner and is called once per run, so requests that join an in-flight run share one row and one `debate_log_id`. Until that change lands, the endpoint calls the writer right after the export. A logging failure never fails the response, is logged at ERROR with a traceback, and is visible in the response (`debate_log_id: null`).
- **Agents expose their evidence**: an optional `evidence` mapping on `AgentPosition`, filled in Round 1 by the three agents (indicator values, hashed headline ids, raw macro signal values) so the log does not re-fetch anything.
- **`backend/scripts/score_debates.py`**, run by hand: reads `ohlcv` from `app.db` read-only, writes only to the log file, scores a row only when `ohlcv` holds the fifth market session after `as_of`, idempotent, offline. It reports range coverage at the stated band, verdict and per-agent hit-rates for directional stances against the base rate and a market-demeaned baseline, and the effective sample size with a clustered interval, not a naive one.
- **`backend/scripts/verify_log_sample_size.py`**: reproduces the effective-breadth and effective-sample figures this design relies on (a verification task, scripts preserved).
- **Not built**: a scheduler or nightly basket, a UI for live hit-rate, any change to the Confidence display, retraining, and a backfill of the six existing report files (documented in design Decision 9).

## Impact

- **Backend**: new `backend/app/db/debate_log.py` (path, connection, table, init-on-first-write; `schema.py` and `init_db` are not touched); new `backend/app/services/debate/outcome_log.py`; `engine.py` (`AgentPosition.evidence`), `technical.py`, `news.py`, `macro.py` (fill it, nothing else); the runner's post-run hook registration (`harden-debate-runtime`) or, until it lands, `backend/app/api/debate.py` right after the export, plus one additive response field; new `backend/scripts/score_debates.py` and `verify_log_sample_size.py`; new tests `test_debate_outcome_log.py`, `test_score_debates.py`.
- **API**: one additive, nullable field on the debate response, `debate_log_id`. Verdict enum values and every existing field are unchanged.
- **Frontend**: none (the extra field is ignored).
- **Dependencies**: none new (`hashlib`, `json`, `numpy`, `pandas` are already used).
- **Docs** (edited at apply time, not by this proposal): `DATA_DICTIONARY.md` (the log file and table), `KNOWN_ISSUES.md` (the log file is irreplaceable: back it up, never clean `data/*.db` blindly), `DISCUSSION_prediction_outcome_tracking.md` (status line).
- **Sibling changes and ordering**: apply after `debate-data-guards`, `calibrate-volatility-range` and `harden-debate-runtime`. `debate-data-guards` provides `assess_eligibility`, `data_as_of`, `data_age_sessions`, `agents_degraded`, `eligibility`, the `INSUFFICIENT_DATA` verdict; `calibrate-volatility-range` provides `sigma_daily_pct`, `range_5s_pct`, `range_k`, `range_coverage` on the result (its `range_hit_rate`, now defined on non-overlapping windows, is still not logged); `harden-debate-runtime` provides the runner and its post-run hook, which runs once per run because in-flight duplicate requests join one run. The columns fed by the first two have no source before then; without the third, the endpoint calls the writer directly. `retire-direction-model` deletes `ml/backtest.py`, `backtest_predictions` and `verify_backtest_predictions.py`: the scoring script copies the t+5 idea and imports none of them. `harden-debate-runtime` and `debate-data-guards` also edit `engine.py`, `news.py` and `macro.py`; the `evidence` additions are small and independent, but the author must reconcile them. `align-rules-and-disclaimer` rules on Rule 4; this change shows no hit-rate to any user and only produces the measurement a ruling could later rest on.
- **Domain rules**: Rule 1 honored unchanged (outcome `r5 = ln(close[t+5]/close[t])`, five trading sessions; the Rule 1 ruling under the pivot belongs to `align-rules-and-disclaimer` and does not change this unless the horizon changes, in which case one constant does). Rule 2 honored (the DB stores the log return like `features.target`; the script prints percentages; no UI). Rule 3 not touched. Rule 4 not changed: nothing here replaces or displays Confidence. Rule 5 not touched (rows are keyed by agent id, no label is emitted). Rule 6 not triggered (no Advice, Confidence or Sentiment is rendered; the script is developer tooling). No sign-off is needed.
- **Data handling**: no LLM free text and no third-party headline text is stored (design Decision 4); the database is local and gitignored; the script makes no network calls.
